# scene-to-characters —【上游】場次文件 → 每角色一檔

產線三段的第 1 段。輸入一份「按場次組織」的文件，輸出角色總表與「以角色為中心」的抽取檔，每角色一份；再依核准的角色表，批次補建尚不存在的角色資料夾。**只做角色盤點、拆分抽取與空資料夾初始化**——不產 CHARACTER_SPEC、不寫提示詞、不生圖。

```
[本段] 場次文件 → 角色表＋每角色抽取檔＋缺少的角色資料夾
       →  (中游) characters-to-sheets → (下游) sheets-to-codex
```

## 路徑/檔名約定（交接契約）
- **`<repo-root>` ＝生圖 repo 根目錄**：直接 clone `Codex_Image_Agent` 時就是 clone 出來的資料夾；從外層 `claude-Godzilla-z` 專案使用時是 `output/`。**不要**兩者相加。
- **路徑＝暫定可改**：輸出目錄預設 `<來源檔同層>/characters_extracted/`；執行者可改，只要維持「每角色一檔」。
- **檔名＝固定不可改**：每角色 `<角色英文小寫名>.md`（例 `kritz.md`）；群像 `_background-and-crowd.md`；索引 `_INDEX.md`。英文名一經決定即固定，後續兩段都靠它對應。
- **角色表＝建資料夾的唯一清單來源**：預設使用 `<repo-root>/全角色總表.md`；若使用者明確指定另一份核准角色表，則以該檔取代。不得依臨時推測、目錄掃描或角色抽取檔名額外建立表外角色。
- **角色資料夾固定位置**：`<repo-root>/Story_Character/<分類>/<中文角色資料夾名>/`。分類限 `01_主角陣營`、`02_反派陣營`、`03_三大貴族`、`04_遠征士兵`、`05_傳說與背景`；角色表無法判定分類者放 `_unsorted/` 並回報。

## 標記鐵律（全產線一致，最重要）
- 文本明載 → `CANON` ＋出處 `(SCENE NN)`，逐字忠於原文
- 鏡頭/台詞可合理推得 → `DESIGN-PROPOSAL`，一句話寫推理依據
- 缺口、多種讀法、會改變辨識度的分歧 → `PENDING-USER-INPUT`，**不自行決定**
- 絕不把推測寫成正典；絕不發明文本沒有的數值（身高/顏色可提案但標 DESIGN-PROPOSAL）

## 執行前先確認（強制）
1. **來源檔**：哪份場次文件？（例 `<repo-root>/Story_Character/預告片_按場次重新整理.md`）
2. **範圍**：抽全部出場角色，還是指定名單？
3. **輸出目錄**：預設 `characters_extracted/`，或另指定？
4. **群像處理**：群體角色（居民/信徒/難民/士兵/守衛/傳令兵）是否要各建檔（預設否，統一列 `_background-and-crowd.md`）。
5. **英文名**：文件多為中文名——若無既定英文譯名，先提一份「中文→英文小寫檔名」對照給使用者確認，再開始寫檔（檔名一旦定案不可改）。
6. **角色表**：確認建資料夾使用的核准角色表；預設 `<repo-root>/全角色總表.md`。表內每位具名角色必須能解析出「中文角色資料夾名、英文識別名、分類、目標路徑」。分類未定可標 `PENDING-USER-INPUT` 並先放 `_unsorted/`，但不得自行加入表外角色。

## 詳細步驟

### 步驟 1｜建立或讀取角色總表（先掃一遍全文）
1. 逐場讀每張場次卡的兩列：「實際出場角色」與「場景外角色／聲音」。
2. 把所有**有名有姓**的角色收成一張總表；同時標記每次出現是「實際出場」還是「場景外/聲音」。
3. **別名/時期整併**：同一人的不同時期稱呼要合併為同一角色，並在檔內記為「時期變體」而非兩個人。常見型態：
   - `童年克里茲`／`年幼克里茲`／`克里茲` → 同一角色 `kritz`，記「時期：童年(SCENE 00)、少年(SCENE 01-13)、青年(SCENE 14+)」
   - `年幼蕾瓦娜斯`／`蕾瓦娜斯` → 同一角色
   - 帶姓全名（`歐文・迪克斯`／`強尼・德加`／`阿拉法爾特・斯洛柏格`）→ 取一個固定英文檔名，全名記在檔內
4. **群像/背景**（無名群體：泰倫居民、教會信徒、工人、三萬名難民、赫克托士兵、叛軍士兵、傳令兵、守衛、軍官、主教、信徒）→ 不建個別角色檔，記進 `_background-and-crowd.md`。
5. 屍體/道具化的角色（如「哈努爾的屍體」出現在 SCENE 09）→ 併回該角色本人檔，註明該場為「屍體/道具形式出現」。
6. 若已有核准角色表，先以其角色名與英文識別名為準，再補入本輪來源中的新線索；遇到表外具名角色，先列入待核准差異，不得直接為其建資料夾。
7. 在角色表或 `_INDEX.md` 建立資料夾映射：`中文角色資料夾名 → 英文識別名 → 分類 → 目標路徑`。中文資料夾名優先取角色表明列的「資料夾名稱／角色」欄，否則取角色節標題；不得自行改名。

### 步驟 2｜依角色表批次補建缺少的角色資料夾
1. 逐筆讀取核准角色表中的具名角色；群像、背景群體與表外候選不建立角色資料夾。
2. 依步驟 1 的映射組成目標：`<repo-root>/Story_Character/<分類>/<中文角色資料夾名>/`。
3. 目標資料夾**不存在**才建立；已存在則標記 `EXISTS-FROZEN` 並完全略過，不改其中任何檔案。
4. 本步驟只建立角色資料夾本身，不建立 `CHARACTER_SPEC.md`、`PROMPTS.md`、`rejects/`、PNG、README 或封存檔。
5. 分類無法由角色表明載資訊判定時，建立於 `<repo-root>/Story_Character/_unsorted/<中文角色資料夾名>/`，並把分類列為 `PENDING-USER-INPUT`。
6. 回寫 `_INDEX.md` 的目標路徑與狀態：`CREATED`／`EXISTS-FROZEN`／`UNSORTED-PENDING`。資料夾清單必須與角色表逐筆對得上。

### 步驟 3｜逐角色收集線索（每個有名角色走一遍全文）
對總表中每個角色，掃過所有場次，收集並分區：
1. **出場場次**（實際在鏡頭空間）：`SCENE NN｜<一句情境>（該場功能）`
2. **場景外／聲音出現**：只被回憶/提及/旁白/聲音帶到的場次，另列。
3. **台詞彙整**：逐句抄錄，**每句帶 `[SCENE NN]` 來源**；忠於原文不改寫。
4. **外貌線索**：從「可拆成的畫面／鏡頭」與台詞抽取臉/髮/瞳/膚/體型/身高的描述。例：SCENE 01「皇后空洞的金色眼睛」→ 阿格妮絲瞳色 `CANON (SCENE 01)`。
5. **服裝與道具線索**：服裝、武器、持物、配件。例：SCENE 04「班尼迪克雙手將聖劍橫放」→ 聖劍為克里茲道具 `CANON (SCENE 04)`；SCENE 08「王冠與長袍被狂風吹動」→ 班尼迪克服裝 `CANON (SCENE 08)`。
6. **血緣與關係線索**：例 SCENE 01 皇后稱克里茲「惡魔之子」、為其母 → 克里茲⇔阿格妮絲 母子 `CANON`；SCENE 27 安德烈召「子女」菲利浦、賽希莉亞 → 父子女 `CANON (SCENE 27)`。
7. **情緒／表情線索**（供下游八表情設計）：記各場該角色的情緒狀態＋場次。例克里茲：冷峻壓抑(通篇)、崩潰(SCENE 18 項鍊被奪)、帝王之怒(SCENE 15 頒軍令)。

### 步驟 4｜標記與待確認
- 每條線索按鐵律標 `CANON (SCENE NN)` / `DESIGN-PROPOSAL` / `PENDING-USER-INPUT`。
- 外貌關鍵項（臉/髮/瞳/身高）文本沒寫的 → 明列在「待確認」，不要自己編。

### 步驟 5｜寫出每角色檔（用下方範本）

```markdown
# <中文名> <English Name>

> 檔名：`<english-name>.md`｜時期變體：<若有，列各時期與對應場次>

## 出場場次（實際在鏡頭空間）
- SCENE NN｜<一句情境>（該場核心功能）

## 場景外／聲音出現
- SCENE NN｜（回憶/提及/旁白/聲音/屍體形式）

## 台詞彙整（逐場，帶來源）
- [SCENE NN]「<台詞逐字>」

## 外貌線索
- 臉：<線索>（標記＋出處）
- 髮：<線索>（標記＋出處）
- 瞳：<線索>（標記＋出處）
- 膚：<線索>（標記＋出處）
- 體型/身高：<線索>（標記＋出處）

## 服裝與道具線索
- 服裝：<線索>（標記＋出處）
- 武器/持物/配件：<線索>（標記＋出處）

## 血緣與關係線索
- <與某角色的關係>（標記＋出處）

## 情緒／表情線索（供八表情設計）
- <各場情緒狀態>（帶場次）

## 待確認（PENDING-USER-INPUT）
- <會明顯改變辨識度、文本無法決定的項目>
```

### 步驟 6｜群像檔 `_background-and-crowd.md`
列每個群體：名稱、出現場次、在場功能（背景/氛圍/動作）。不做外貌鎖定。

### 步驟 7｜總索引 `_INDEX.md`
- 全角色清單（中文名 → 英文檔名）
- 資料夾映射（中文角色資料夾名 → 英文識別名 → 分類 → 目標路徑 → 建立狀態）
- 每人出場場次數、僅聲音場次數
- 主要角色（出場多）／次要／僅聲音 分層
- 群像另列
- 血緣關係一覽（成對列出，供下游 Kinship）

### 步驟 8｜自查（交付前）
- [ ] 每一場的「實際出場角色」都有被歸進某個角色檔或群像檔（無漏人）
- [ ] 每句台詞都帶 `[SCENE NN]` 來源
- [ ] 時期變體已整併為同一檔，未拆成兩個人
- [ ] 外貌關鍵缺口都在「待確認」，未自行編造
- [ ] 血緣關係成對一致（A 檔列 B、B 檔列 A）
- [ ] 角色資料夾清單只來自核准角色表，未建立任何表外角色
- [ ] 角色表中每位具名角色都有唯一目標路徑與 `CREATED`／`EXISTS-FROZEN`／`UNSORTED-PENDING` 狀態
- [ ] 已存在的角色資料夾及其 SPEC、PROMPTS、PNG 完全未被修改
- [ ] 新建角色資料夾是空的；SPEC＋PROMPTS 留給中游成對寫入

## 完成後回報
結論先行：角色表路徑、表內具名角色數、抽出角色數（主要/次要/僅聲音）、群像數、資料夾 `CREATED`／`EXISTS-FROZEN`／`UNSORTED-PENDING` 數量、每人欄位覆蓋率摘要、PENDING-USER-INPUT 總表、輸出路徑。提醒下游：只進入上游已建立的角色資料夾，由 **characters-to-sheets** 產 SPEC＋PROMPTS。不貼檔案全文。

## 邊界
不生圖、不產最終 CHARACTER_SPEC.md 或 PROMPTS.md（下游）、不改來源檔。只依核准角色表補建缺少的空角色資料夾；不碰任何已存在角色資料夾。只認「按場次組織」的輸入；來源是別種結構時先請使用者確認。
