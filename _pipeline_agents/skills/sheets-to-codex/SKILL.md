# sheets-to-codex —【下游】角色包 → Codex 兩階段產圖與驗收

產線三段的第 3 段。輸入中游產好的 `<repo-root>/<專案名>/`（每角色 SPEC＋PROMPTS），驅動 Codex／圖像模型**照 PROMPTS 逐張生圖**，並主持核准與 REJECT 驗收。**Claude 不生圖**——本段是產圖的編排與驗收指令；實際輸出 PNG 由 Codex 執行。

```
(上游) scene-to-characters → (中游) characters-to-sheets → [本段] 驅動 Codex 生圖＋驗收 → PNG
```

> **`<repo-root>` ＝生圖 repo 根目錄。** 直接 clone `Codex_Image_Agent` 時就是 clone 出來的資料夾；
> 從外層 `claude-Godzilla-z` 專案使用時是 `output/`。**不要**兩者相加。

## 單次生成政策（最高優先）

1. 使用者每次提出一次生圖要求，最多呼叫 ImageGen／圖片生成工具一次，只產出一張新圖。
2. 生成後立即呈現並停止；不得在同一輪自動生成第二張、備選圖或修正版。
3. REJECT 清單是回報用檢查表。發現偏差時列出問題並等待使用者，不得自行移檔、淘汰、修改或重生成。
4. 只有使用者看過圖片後明確要求修改或重生，才可把上一張未核准候選移入 `rejects/`，再生成一張新候選；生成後仍立即停止。
5. 本政策覆蓋既有 `PROMPTS.md` 中任何「REJECT 後重生成」文字；一律解讀為「標示問題並等待使用者決定」。

## 人類手指完整性（強制）

1. 適用所有人類與人形角色，以及每張圖片、每個視圖、每個圖格中任何可見的人類手部。每隻手必須**恰好五指：四根手指加一根拇指**；禁止多指、缺指、重複指、融合指、漂浮指或錯位拇指。
2. 每次送出生圖提示詞時，即使角色 `PROMPTS.md` 未寫，也必須追加：`Every visible human hand must have exactly five digits: four fingers plus one thumb, anatomically attached; no extra, missing, duplicated, fused, floating, or malformed digits.`
3. 多視圖、多人或多格圖片必須逐一放大、逐手計數，不得只抽查正面或其中一人。若該張要求完整手部，裁切、遮擋、藏手或解析度不足以確認五指，同樣標為 `HAND-ANATOMY-REVIEW-REQUIRED`。
4. 03 表情圖、06 道具圖等原本不需要手的圖片，不得為了驗收自行加入手；但模型若意外畫出可見人手，仍須套用五指規則。
5. 發現手指錯誤時，回報確切視圖／圖格、左右手及觀察到的指數，列為 REJECT 並等待使用者；不得自動重生。
6. 使用者明確要求修手時，只修改雙手與必要的最小腕部邊緣，鎖定臉、身份、髮型、服裝、身形、姿勢、構圖、光線與背景；舊候選依規則存入 `rejects/`，且仍只生成一張修正版。

## 前提檢查（六項全過才能執行本段）

- [ ] 設定圖為 01–07 格式（非人形 01–06）；已有正式 PNG 的凍結角色不進入本段
- [ ] `CHARACTER_SPEC.md` 完整：版本 ID、Body Metrics Lock、固定 hex 色票、身份正本欄、Kinship Lock
- [ ] `PROMPTS.md` 完整：檔頭 Codex 生成清單五項齊（檔名／閘門／一致性／input images／既有 PNG 標記）
- [ ] `<repo-root>/<專案名>/STYLE_ANCHOR.md` 存在；可為等待首次請求的 `PENDING-FIRST-REQUEST`，或已登記首角色且狀態為 `PENDING-APPROVAL`／`ACTIVE`
- [ ] 無阻擋生圖的 `PENDING-USER-INPUT`（檔頭無「未定案不得生成 01」鎖）——有鎖的角色先擱置，回報使用者定案
- [ ] `PROMPTS.md` 有明確的 `## 01`–`## 07` 生圖段落（非人形 `## 01`–`## 06`）

任一項不成立 → 回報缺項並停止，**不得開始生圖**。

## 執行前解析（強制）
1. **專案**：以目前開啟的 Git 根目錄與已找到的角色包自動解析，不重複詢問。
2. **本輪範圍**：以使用者訊息中的指定角色為準；若畫風錨尚未登記，該零圖片角色就是首角色。
3. **生圖執行者**：優先使用目前 Codex 環境可用的 ImageGen／圖片生成工具，產出 PNG 放角色資料夾（檔名照生成清單）。

只有上述資訊無法從 repo、使用者訊息或可用工具判定時，才詢問缺少的單一必要資訊。

## 詳細流程

### 階段 0｜閘門檢查
1. 讀 `STYLE_ANCHOR.md`：若首角色是 `PENDING-FIRST-REQUEST`，把本次指定的零圖片角色寫入「首角色」，把其預定 `01-<slug>-front-fullbody.png` 相對路徑寫入「畫風錨圖片」，登記當天日期，狀態維持 `PENDING-APPROVAL`。此後在使用者核准前，**本專案只能做該首角色的 01**，其餘全部擋住。
2. 血緣專案：家族錨點角色的 01 未核准前，其他家族成員擋住。
3. 有 PENDING 鎖的角色：擱置，列入回報。

### 階段 1｜首角色 stage-1（生 01，建立畫風錨）
1. 從首角色 `PROMPTS.md` 取 `## 01` 提示詞與檔頭 (d) 的 input images（＝bootstrap 畫風依據）。
2. 交 Codex 生成 `01-<first>-front-fullbody.png`（**只生這張**）。
3. 生成後**停止**，把圖呈現給使用者核准。
4. **REJECT 驗收**（對照 PROMPTS 文末清單）：A-pose？零道具？平光？臉清晰？身材/色票符合 SPEC？所有可見人手是否逐手確認為四指加一拇指？
   - 發現偏差 → 把問題隨圖片一併回報並等待；**不得自行移檔或重生成**。
   - 使用者明確要求修改 → 上一張未核准候選存 `<first>/rejects/`、記原因，只重生成一張並再次停止。
   - 使用者明確核准 → 才進階段 2。

### 階段 2｜登記畫風錨
1. 使用者核准首角色 01 後，把 `STYLE_ANCHOR.md` 狀態改 `ACTIVE`，畫風錨圖確立為該 01。
2. 自此所有角色 2..N 的畫風以此 01 為唯一參考。

### 階段 3｜首角色 02–07
1. 使用者指定或核准繼續後，只生成下一張 `02`→`07`（非人形到 06）。input images：Image 1＝首角色自己的 01。
2. 每次只生成一張、呈現並停止。REJECT 清單只回報偏差；使用者明確要求修改後才把舊候選存 `rejects/` 並重生成一張。
3. 06 是唯一能出現武器道具的張；01/02/04/05/07 出現武器即 REJECT。
4. 人類角色每張都套用「人類手指完整性」；02 四視圖、07 身體參考等多視圖圖面必須逐視圖、逐手檢查。

### 階段 4｜角色 2..N（依序，每人一輪兩階段）
對每個後續角色：
1. **stage-1 生 01**：input images＝Image 1 空、Image 2＝首角色 01（畫風）。生成後停、呈使用者核准。
   - REJECT 清單多一項：**畫風與畫風錨（首角色 01）一致？** 不一致時只回報並等待使用者。
2. 核准後，使用者每次指定或核准繼續才**生下一張 02–07**：input images＝Image 1＝本角色自己的 01（身份）、Image 2＝首角色 01（畫風）。
3. 每次只生成一張、呈現並停止；只有使用者明確要求修改，才將舊候選存 `rejects/` 並重生成一張。
4. 血緣角色：家族錨點先完成，其成員 01 的 Kinship 驗收對照家族錨點的臉。
5. 所有人類角色的每次生圖與驗收都必須套用「人類手指完整性」，不得因已有身份參考圖而省略。

### 階段 5｜逐張驗收細則（REJECT 判準）
每張都查（對照該角色 PROMPTS 文末清單與 SPEC）：
- 臉型/身份、髮型/髮色、身材比例（Body Metrics）、服裝結構、左右不對稱未鏡像、色票未漂移、該張構圖規則（視圖數/順序/A-pose/零道具/平光）、畫風一致（2..N）、血緣相似（有血緣）。
- 人類／人形角色：放大每個視圖與圖格，逐手確認「四根手指＋一根拇指＝五指」；任何多指、缺指、融合、錯位或無法確認均列為 `HAND-ANATOMY-REVIEW-REQUIRED`，並在回報中指出位置與左右手。
- 任一漂移：隨圖片回報問題並停止，等待使用者核准或要求修改。只有使用者明確要求修改時，才把上一張未核准候選移到 `<角色>/rejects/<檔名>-reject-<n>.png`、記一行原因、用修正後提示詞只重生成一張；**絕不覆蓋既有正式 PNG**。

## 完成後回報
結論先行：本次產出的一張 PNG、技術檢查觀察、逐視圖／逐手的五指檢查結果、等待使用者核准或修改；另附專案進度（各角色 01 核准狀態、02–07 完成數）、畫風錨狀態（PENDING/ACTIVE）、使用者要求修改的歷史、仍擱置的角色（PENDING 未定案）。

## 鐵律
Claude 不生圖（生圖是 Codex）；一次使用者要求只生一張；所有可見人類手部逐手恰好五指；生成後立即停止；技術驗收不觸發重生；只有使用者明確要求修改才重生成一張並把上一張未核准候選放 `rejects/`；不刪不覆蓋既有 PNG；首角色 01 未核准前不得開後續角色；有 PENDING 鎖的角色不生 01。
